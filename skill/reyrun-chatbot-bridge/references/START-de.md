## Eine Startdatei für den Gerätebesitzer

Wenn jemand die Adresse dieser Seite einfügt, kläre, auf welchem Gerät die Aufgabe erledigt werden soll. Prüfe zuerst den bereits erlaubten Zugriff. Ist eine Einrichtung nötig, gib eine fertige Startdatei für dieses Gerät aus. Eignet sich die veröffentlichte Datei nicht für den Auftrag, erstelle ein passendes Skript nach den folgenden Schritten. Zeige der Person jeweils nur den nächsten nötigen Schritt.

1. Prüfe den aktuellen Zustand. Ist die Aufgabe bereits erledigt, überprüfe das Ergebnis und schließe sie ab. Bleibe im freigegebenen Ordner.
2. Nutze zuerst das vom Projekt unterstützte Verfahren. Wiederhole einen vorübergehend unterbrochenen Download nur begrenzt oder verwende eine offizielle Kopie derselben Version. Prüfe vor dem Start die erwartete Prüfsumme oder Signatur. Fehlen Schreibrechte, nutze einen unterstützten Benutzerordner, sofern du dort das Ziel erreichst.
3. Erkläre beim Koppeln, bei der Dateiauswahl und bei einer Systemfreigabe, was der Gerätebesitzer bestätigen soll. Warte auf seine Entscheidung und halte bei einer Ablehnung an. Nutze die Übergabe einer einzelnen Datei nur für Aufgaben, die sich damit erledigen lassen.
4. Sichere den bisherigen Zustand. Prüfe nach einer Unterbrechung, was tatsächlich abgeschlossen ist, und setze beim ersten offenen Schritt fort. Bewahre bei einem erneuten Lauf vorhandene Einstellungen und Sicherungen.
5. Prüfe das Ergebnis durch eine echte Aktion aus dem Chat. Lies etwa eine vorher unbekannte Datei im freigegebenen Ordner und vergleiche ihren Inhalt. Nenne das Ergebnis oder das konkrete Hindernis. Zähle Downloads, Dateiöffnungen, Systemfreigaben und Clientaktionen getrennt. Versprich keine feste Anzahl von Klicks.

## Prüfung nach dem Start

Für Filesystem rufe list_allowed_directories auf. Schreibe im zurückgegebenen Arbeitsordner eine Testdatei und lies sie wieder. Bei abweichendem Inhalt halte an. Rufe für Task Bridge bridge_status und danach read_checkpoint auf. Verwende für den ersten save_checkpoint die Revision 0. Nach einem Verbindungsabbruch rufe read_checkpoint mit derselben Aufgabenkennung auf.

## Wenn ein anderer Chat übernimmt

## Wie können vier Chats gleichzeitig arbeiten?

Geben Sie jedem Chat eine eigene Aufgabenkennung und einen eigenen Ordner. Text, Dateivergleiche und Prüfungen können getrennt laufen. Überlassen Sie Änderungen an einer Spielinstallation einem einzigen Chat. Jede Browsersitzung bekommt ein eigenes Profil. Auf einem gemeinsamen Desktop steuert immer nur eine Sitzung den Mauszeiger.

## Was passiert, wenn die Verbindung abbricht?

Geben Sie dem neuen Chat dieselbe Aufgabenkennung. Lassen Sie ihn die letzte Notiz lesen und prüfen, welche Dateien fertig sind. Prüfen Sie nach einem abgebrochenen Download oder Kopiervorgang erst die vorhandene Datei. Haben zwei Chats denselben Eintrag geändert, lesen Sie vor dem nächsten Schreibvorgang die gespeicherte Version.

## Welchen Zugriff erhält der Chatbot?

Die Startdatei für Dateien gibt einen REYRUN-Arbeitsordner frei. Beim Spiel kommt der ausgewählte RDR2-Ordner hinzu. Für das Browserbeispiel genügt eine einzige ausgewählte Datei. Beim ersten Öffnen kann das Betriebssystem um Erlaubnis bitten. Erscheint eine unerwartete Abfrage, können Sie beim Browserbeispiel bleiben.

## Wie finde ich die Ursache eines Programmfehlers?

Legen Sie eine Kopie des Fehlerprotokolls im REYRUN-Arbeitsordner ab. Bitten Sie Ihre KI, den letzten Fehler zu lesen und zu erklären. In einem normalen Webchat genügt der betreffende Textausschnitt. Das Browserbeispiel meldet Prüfsumme und Zeilenzahl. Der Protokolltext bleibt auf dem Gerät.

[Anleitung für Ihre KI](https://reyrun-chatbot-bridge.runcisreinis.chatgpt.site/ai/de.md) · [Tests und Quellen](https://github.com/runcisreinis-glitch/REYRUN-Chatbot-Bridge/tree/main/research)

## Wo findet der Client die Verbindungseinstellungen?

Unter Windows prüft der Launcher %APPDATA%/Claude, auf dem Mac ~/Library/Application Support/Claude. Vor einer Änderung sichert er claude_desktop_config.json und ergänzt nur den gewählten reyrun-…-Eintrag. Fehlt der Client, verweist START.txt auf das Browserbeispiel. Andere kompatible MCP-Clients können die erzeugte runtime/reyrun-…-client.json verwenden. Deren Programmpfad gilt für diesen Computer.
